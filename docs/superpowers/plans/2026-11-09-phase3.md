# Phase 3 — Pre-Assessment, Deep Scan, authenticated testing, wordlists, retest, reports — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn on the Pre-Assessment and Deep Scan profiles. Deep Scan does signed-in, multi-account testing through a guarded ZAP engine, plus SecLists-based discovery and fuzzing, selective retest, and management/technical reports with server-generated PDFs.

**Architecture:**
- **ZAP container (compose profile `dast`).** One shared ZAP daemon, capped at `-Xmx1g`, sits on an internal-only Docker network. Its only way out is a new **egress guard proxy**. The proxy applies the Phase 2 `ipguard` + scope + internal-rule logic on every connection and pins each connection to the checked IP.
- **Worker-side modules.** Everything ZAP isn't needed for runs in the worker over the existing `SafeClient`: login, per-account crawling comparison, CMS/config checks, wordlist discovery and fuzzing, testssl.sh.
- **Engine slots.** A new scheduler setting `engine_slots` (default 1) limits ZAP-based jobs inside the existing global gate.
- **Reports.** One report model (JSON) feeds both the React preview and a WeasyPrint PDF. The worker generates them asynchronously.

**Tech Stack:**
- **Existing:** FastAPI, SQLAlchemy 2, Alembic (hand-written SQL migrations), Postgres 16, React 18 + TS + Vite, Vitest.
- **New:**
  - `zaproxy/zap-stable` (pinned digest);
  - testssl.sh (pinned git tag, installed in the worker image);
  - SecLists (pinned release, subset vendored at build);
  - retire.js `jsrepository.json` and endoflife.date data (pinned, vendored);
  - Python `cryptography`, `weasyprint`, `jinja2`.

**Spec:** `docs/superpowers/specs/2026-11-09-phase3-design.md` (approved). Read it with this plan; §7 holds the resolved decisions.

## Global Constraints

- **Precedence:** `DESIGN_SYSTEM.md` §1.2 → `DESIGN_SYSTEM.md` → docx pack → spec. Extend `docs/API.md` in the same commit as any endpoint change.
- **No engine traffic bypasses the guard.**
  - ZAP's only network path out is `egress:3128`.
  - Worker HTTP goes through `SafeClient`.
  - Raw sockets (nmap, testssl.sh) target only `Ctx.safe_ip()`.
- **Credentials are write-only after save.** Never in responses, logs, evidence, reports, audit detail, queue rows or ZAP logs.
  - The API encrypts with `CREDENTIALS_PUBLIC_KEY` only.
  - Only the worker holds `CREDENTIALS_PRIVATE_KEY`.
  - Both values are validated at startup (`app/core/startup.py`).
- **Never a false success.** Budget exhaustion, a missing engine, lockout or OOM must end as `completed-warnings` / `inconclusive` / `unavailable` with a plain detail. Reports count those as **Not tested**.
- **Budgets** (admin-configurable, stored in `scheduler_config.profile_limits`):
  - `pre` = 30 min, `deep` = 180 min, counting run time only.
  - Stage split: crawl 30% / active 50% / access 20%; leftover rolls forward.
- **Engine slots:** `scheduler_config.engine_slots` default 1, range 1–3. Engine modules = `{"crawl", "dast", "api"}`.
- **Never replayed or fuzzed:** URLs matching `(?i)logout|signout|sign-out|delete|remove|password|deactivate|unsubscribe`, plus assessment exclusions, plus the login and OTP forms.
- **Wordlists** come only from SecLists `Discovery/` and `Fuzzing/`. Never `Passwords/`, `Usernames/` or any credential list.
- **Login styles:** `single` (username + password + optional code in one form) and `two-step` (password form, then an OTP page taking the code).
- **Memory:** ZAP `-Xmx1g`. No other new long-running service over ~100 MB.
- **Compose:** `docker-compose --profile dev --profile dast up -d --build --scale worker=2` is the full dev command. Never run `docker-compose down -v`.
- **Copy:** DESIGN_SYSTEM §8 (sentence case, verbs, IST dates, no exclamation marks). Status words come from the §5 vocabularies only.
- **Commits** end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Tests: `docker-compose --profile test run --rm --build test` and `cd frontend && npm run build && npm test`.

## Review Focus

1. **A ZAP request whose target host resolves to a private or metadata IP mid-scan (rebinding)**, or a redirect to an out-of-scope host. The proxy must refuse at connect time.
   - Test: Task 1 `test_connect_rebinding_refused`, `test_plain_http_out_of_scope_refused`.
2. **A login that "succeeds" with HTTP 200 but stays on the login page** (bad password, wrong field name). The account must be reported as failed, never treated as signed in.
   - Test: Task 4 `test_login_200_without_indicator_fails`.
3. **Two jobs claimed at once when both need ZAP while `engine_slots=1`.** The second must wait while a Quick Scan can still start.
   - Test: Task 5 `test_engine_slot_blocks_second_engine_job_not_quick`.
4. **A wordlist selection larger than the remaining request cap.** It must be refused with the count, not silently truncated.
   - Test: Task 9 `test_wordlist_over_cap_refused`.
5. **Retest when the account used by the original finding was deleted.** The finding must become Not retested with a reason, and the job must not fail.
   - Test: Task 10 `test_retest_missing_credential_not_retested`.

### Task 4: Credentials, login engine, sign-in setup API

**Files:**
- Create: `backend/app/core/crypto.py`, `backend/app/targets/login.py`, `backend/app/api/signin.py`
- Modify: `backend/app/main.py`, `docs/API.md`
- Test: `backend/tests/test_crypto.py`, `backend/tests/test_login.py`, `backend/tests/test_signin_api.py`

**Interfaces:**
- `crypto.seal(plaintext: str) -> bytes` uses the public key: ephemeral X25519 + HKDF + AES-GCM. `crypto.open_sealed(blob: bytes) -> str` uses the private key and raises `RuntimeError` when the private key is absent.
- `login.LoginSetup` is a dataclass mirroring the `login_setups` row, with plaintext `bypass_code: str | None`.
- `login.perform_login(client: SafeClient, setup: LoginSetup, username: str, password: str, deadline: float) -> LoginResult`, where `LoginResult(ok: bool, reason: str, cookies: dict[str, str])`.
  - It GETs the login page and carries hidden inputs (CSRF tokens), then POSTs the fields.
  - In `two-step` style it then GETs `otp_url` and posts `otp_field=bypass_code`.
  - `ok` is True only when `logged_in_indicator` appears (as text, or as a URL regex when it starts with `url:`).
  - Reasons: `"Signed in"`, `"The login page did not show the signed-in marker"`, `"The OTP step did not accept the code"`, `"Account appears locked"` (status 423 or text match `(?i)locked|too many attempts`), `"Could not reach the login page"`.
- **API (owner only via `can(level,'scan')`, DESIGN_SYSTEM §11):**
  - `GET /api/assessments/{id}/signin` → `{setup: {...no secrets..., bypass_code_set: bool}|null, accounts: [{id, role_label, username_hint, last_test, last_tested_at}]}`. `username_hint` shows the first 2 characters + `•••`.
  - `PUT /api/assessments/{id}/signin` → setup fields + optional `bypass_code`. Omitted keeps the existing value; `""` clears it.
  - `POST /api/assessments/{id}/accounts` → `{role_label, username, password, test: bool, authorized: bool}`. When `test` is set it requires `authorized === true` and validation outcome allowed or approved. It runs `perform_login` in the API with the plaintext, then seals and stores. Returns the account plus `{test_result: LoginResult.reason}`. Max 10 accounts per assessment.
  - `PUT /api/assessments/{id}/accounts/{cid}` replaces the password/username, with the same test option.
  - `DELETE /api/assessments/{id}/accounts/{cid}` soft-deletes it (sets `deleted_at` and blanks the encrypted fields).
  - Every mutation is audited (role label only). The URL host must be inside the assessment's in-scope hosts, else 422 `{"fields": {"login_url": "The login page must be on an in-scope host."}}`.

- **similarity.same_page(a: bytes, b: bytes) -> float**: strips tags, digits, hex/uuid tokens and CSRF-like values, then uses a word-shingle Jaccard measure. The threshold constant `SAME = 0.9`.
- **access.run(ctx)**:
  - For each account A and each URL in `pages[A] - ⋂pages(all accounts)`, skipping excluded URLs, GET it as every other account B and unauthenticated (None).
  - If the response is 2xx, not the logged-out page (by the `logged_out_indicator` or a login-form detector) and `same_page ≥ SAME` → a suspected finding:
    - `"{B role} can open a page meant for {A role}"`, or `"Page reachable without signing in"`, severity `high`;
    - evidence is both redacted request lines plus 10 lines of each body.
  - Stage deadline → `completed-warnings` + `untested`.
  - **State-changing replays (spec §7.5).** `crawl` also records A's non-GET requests in `run_ctx.requests[A]` as `(method, url, form fields)`, taken from ZAP history for A's context. `access` replays each one as B unless it matches the excluded pattern, and flags it with the same rule as above.
  - Test: `test_access_replays_post_but_not_excluded`.
- **cval.run(ctx)**: re-requests each `suspected` finding produced by `access` and `exposed` in this job with fresh sessions; reproduced → `confidence = confirmed` and a history line `"Confirmed by control validation"`.
